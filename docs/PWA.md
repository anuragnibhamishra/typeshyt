# PWA and result sharing

## Offline and caching strategy

The production service worker is generated by `vite-plugin-pwa` using Workbox `generateSW`. It precaches the built HTML, JavaScript, CSS, SVG/PNG icons (including the SVG favicon used by the web app manifest), and WOFF2 fonts. Navigation requests fall back to `index.html` for the single-page app. Fonts are bundled locally; the app does not fetch Google Fonts at runtime. No runtime third-party requests, analytics, backend, or share-link service are used.

The app shell and built-in typing prompts work offline after the production app has been visited and the service worker has installed. History, preferences, and weak-key aggregates continue to use origin-local `localStorage`; offline use does not change their format. Browser storage can be cleared or evicted, and it is not synchronized between origins, profiles, or devices.

The service worker is disabled in Vite development by default. For manual debugging only, set `devOptions.enabled: true` in `vite.config.ts`, restart `npm run dev`, then unregister the development worker before returning to normal development.

## Update flow

The active service worker continues serving the current app while a new worker installs. Once the new worker is waiting, an accessible toast offers **Reload** and **Dismiss**. Reload is disabled while the typing test is running; the worker is activated and the page reloads only after the user selects Reload. Dismiss hides the toast without discarding the waiting worker.

To test an update locally, build and preview version A, visit it and wait for the service worker to activate. Change a visible app asset, build version B, and publish/serve B at the same origin. Revisit or allow the browser to check for an update; confirm the toast appears, Dismiss leaves the current page intact, and Reload applies the new build. Do not run two preview servers on different origins when testing the update lifecycle.

## Local production and DevTools verification

```bash
npm ci
npm run check
npm run build
npm run preview
```

Open the preview URL printed by Vite (normally `http://localhost:4173`). Service workers require localhost or HTTPS; do not use a `file://` URL. The focused PWA/share tests can also be run with:

```bash
npm run test -- test/pwa.test.tsx test/share.test.ts test/share-components.test.tsx test/components.test.tsx
```

In Chromium DevTools:

1. Open **Application → Manifest**. Check the name, standalone display mode, start URL/scope, theme colors, and that the 192, 512, maskable, and Apple icon files resolve without warnings.
2. Open **Application → Service Workers**. Confirm `sw.js` is registered and activated, and inspect its precache entries. Check **Offline**, reload, and try each mode, history, persistence, and result-card download.
3. In **Application → Storage**, inspect/clear the origin's local storage and unregister the worker when resetting the test environment.
4. To verify fonts offline, reload with DevTools Network set to **Offline** and confirm the app remains styled. The WOFF2 files should be served from the built app rather than a font CDN.

## Sharing and test limitations

The share dialog constructs its PNG only after it opens and regenerates it when the format changes. It uses the saved result's WPM, Raw WPM, accuracy, mode, date, settings, and WPM samples; no typed text, personal data, or per-key statistics are included. Preview object URLs are revoked on format change and close. Native file share and image copy are independently feature-detected; cancellation of the native share sheet is silent.

Canvas in jsdom does not provide dependable 2D rendering or pixel output. Tests mock `HTMLCanvasElement.getContext` and `toBlob`, and assert that the drawing function receives the expected model and format instead of comparing pixels. Check actual typography, contrast, chart layout, and cropping in a browser/device.

## Manual device checklist

- [ ] Android Chrome: install from the browser prompt/menu, launch standalone, use offline after first visit.
- [ ] Desktop Chrome and Edge: install, launch, verify offline, and confirm a result download.
- [ ] iOS Safari: use **Share → Add to Home Screen**, launch standalone, and verify the one-time hint dismissal.
- [ ] Phone native share sheet: share a generated PNG and confirm the recipient receives the image and the short result text.
- [ ] Desktop: download landscape and portrait PNGs and open them to check dimensions/readability.
- [ ] Clipboard: copy the PNG where supported and paste it into an image-capable destination.
- [ ] Update-after-redeploy: start a test with a new build waiting, confirm no automatic interruption, finish the test, then choose Reload and verify the new version.
